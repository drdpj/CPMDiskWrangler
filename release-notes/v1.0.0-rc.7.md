## CP/M Disk Wrangler 1.0.0 release candidate 7

### Microbee
- **New DS80 discs now work.** Discs made here had sector IDs 1-10 on every track, but a real DS80 disc numbers its
  data tracks 21-30 (the reserved ones stay 1-10). The Microbee BIOS looks sectors up by ID, so a new disc was
  "CP/M Err on D: Bad Sector" in ubee512. Data tracks are now numbered from 21, like the real discs.
- **SS80** (80 cylinders, one side) is now a named built-in format, so it can be picked and made as a new disc.
  Real SS80, DS40, DS80 and DS84 discs all still open as known formats, writable.

### New formats and discs it can now find
- **Vector Graphic** CP/M 2.2 (single-density first track, then 26 x 256, skew 5): a built-in format, and the search
  can now find discs of this kind in raw files even when they aren't in the library.
- **Sharp.** Some Sharp formats, such as `sds400`, store every byte inverted (empty space reads `1A`, not `E5`) and
  read each cylinder side 1 first; others, such as the MZ-800's P-CP/M discs, are ordinary. Both of the unusual
  things are now supported: a new `complement` format key and a new "alt, side 1 first" side order, in the Disc format
  dialog too, and a built-in `sharp-sds400`. Discs that look inverted are tried inverted.
- Directory entries carrying the BDOS "written to" flag (bit 7 of an extent's high byte) are no longer thrown out as
  nonsense.

### Choosing between readings
- **Raw files** can't say how a disc was laid out: the same bytes read as 32 x 128 on one side, 16 x 256 on two sides
  or 8 x 512, all with the same score. They now show as one row, with the most plausible geometry first (35, 40, 77 or
  80 cylinders a side, a common sector layout) and the others listed in its notes.
- **Side order** (outback or outout): a track of another shape that a reading puts in the middle of the data now costs
  points, so outback ranks above outout when a disc's odd track is on cylinder 0, side 1, as on Sharp MZ-800 P-CP/M
  discs. When no file reaches the second side the order is still a guess, and the help now says so.
- **How scoring works** has been brought up to date with all of this.

### DSK files, the Open dialog and Linux
- **Standard DSK images** (the original CPCEMU header) can now be made, in File > New disc image and Save As, as well as
  extended ones. The Microbee discs in the wild are standard DSK. Every track must be the same size, so formats with a
  differently shaped first track can't use it and say so.
- The Open dialog now lists upper-case extensions too (`DISK.DSK`, `GAME.IMG`); Linux file dialogs match
  case-sensitively and were hiding them.
- On a GNOME Wayland session the AppImage no longer prints "Ignoring WAYLAND_DISPLAY on Gnome" when started from a
  terminal.

### Known limits
- New Sharp `sds400` discs can't be made yet (its sector IDs differ by side), and a raw `.RAW` of one isn't read; open
  the ImageDisk or DSK version.
- The DS80 fix is based on how the real discs and ubee512 number their sectors. Please tell us if a new disc still
  fails in the emulator.
- A DSK made as a standard image can't hold tracks of different sizes; use an extended DSK for those.
