## CP/M Disk Wrangler 1.7.0

A raw image's track 0 kept at its own size or padded to a full track, and raw discs saved as ImageDisk or DSK get
their single-density track 0 back. It uses the DiskWranglerCore library version 1.3.0.

### New
- **Track 0 padded, or at its own size.** A raw image of a Research Machines, Osborne 8-inch double-density or Vector
  Graphic disc can now keep track 0 padded with zeros to a full track, so that every track is the same length, as
  some emulators and tools want. Tick "Pad track 0 to a full track in the raw image" in New disc image, or choose
  "Raw sector image, track 0 padded to a full track" in Save As; `cpmdw new` and `cpmdw convert` take
  `--track0=padded` (or `--track0=own`). Track 0 at its own size, as real Research Machines images are kept, is still
  the default, and both kinds of file open.
- **Track 0 in Tools > Disc format.** The "Try a format by hand" form has a "Track 0 sectors" row (how many, their
  size, FM or MFM) for a disc whose track 0 has a shape of its own, so such a disc of a format the program doesn't
  know can be read from a raw image that keeps track 0 at its own size, and saved as ImageDisk with the right density.

### Fixed
- A raw image saved as ImageDisk or DSK now gets the tracks a new disc of its format has: a Research Machines,
  Osborne or Vector Graphic disc's track 0 is single density again, and a Microbee DS80's data tracks are numbered
  21-30. Before, every track was written alike.
- A disc read with a track 0 of its own shape, but as a format that doesn't define one, keeps that track 0: saved as
  ImageDisk it is single density, and its ImageDisk copy can be saved as a raw image again (before: "tracks of
  different shapes").
- Changing a raw Research Machines, Osborne or Vector Graphic image with `cpmdw --format=...` no longer pads the end
  of the file.

### Known limits
- A raw image says which kind of track 0 it holds only by its size, so a padded single-sided 80-track Research
  Machines disc (`rm-qd`) is the size of a padded double-sided 40-track one (`rm-dd`, a disc on each side). While the
  second half of the file is blank it opens read-only; `--format=rm-qd` or Tools > Disc format confirms it. Kept at
  its own size, it has no such twin.
- A double-sided disc that gives only side 0 its own track 0 can be kept as a raw image only with track 0 padded.
- TeleDisk images can't be saved as TeleDisk, and TeleDisk 1.x "advanced compression" isn't supported.
- New Sharp `sds400` discs can't be made yet.
- Deleted Torch CP/N files can't be recovered.
- None of the builds is signed: Windows and macOS warn the first time (see the README).

### Building from source
The shared code is the DiskWranglerCore library (version 1.3.0), a git submodule in `core/`. Clone with
`git clone --recurse-submodules`, or run `git submodule update --init` after cloning. GitHub's "Download ZIP" and
"Source code" archives leave `core/` empty; use the complete source archive attached to this release.

### Downloads
Windows installer and zip, macOS disk image, Linux AppImage and .deb, each for Qt 6, with `cpmdw` in each; and the
complete source (`...-source.tar.gz`, with `core/`).
